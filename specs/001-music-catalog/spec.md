# Спецификация: Каталог музыкальных альбомов

Статус: Draft → Approved
Родитель: [../constitution.md](../constitution.md)
Технический план: [plan.md](plan.md)

## 1. Цель

Дать пользователю вести каталог исполнителей, альбомов и песен, где песня — самостоятельная
сущность, способная входить в несколько альбомов под разными порядковыми номерами.

## 2. Предметная область

- **Исполнитель**: имя.
- **Альбом**: название, исполнитель, год выпуска.
- **Песня**: название.
- **Трек** (связь альбом↔песня): порядковый номер песни в конкретном альбоме.

Инвариант предметной области (главный источник сложности задания):
> Одна и та же песня может входить в разные альбомы с разным порядковым номером в каждом из них.

Следствие: номер трека — это атрибут связи «альбом-песня», а не атрибут песни.

## 3. Пользовательские сценарии

### US-1. Каталогизация исполнителя и альбома
Как пользователь, я хочу добавить исполнителя и его альбом (название, год), чтобы начать каталог.

### US-2. Наполнение альбома песнями
Как пользователь, я хочу добавлять в альбом песни с указанием их порядкового номера — либо
создавая новую песню, либо выбирая уже существующую в каталоге.

### US-3. Переиспользование песни
Как пользователь, я хочу добавить в альбом Б песню, которая уже есть в альбоме А (например,
концертная версия на другом альбоме или переиздание), указав для неё номер трека, отличный
от номера в альбоме А, — и увидеть, что в обоих альбомах данные корректны и независимы.

### US-4. Изменение порядка треков
Как пользователь, я хочу переставлять песни местами в треклисте альбома (drag&drop или явное
указание позиции), чтобы исправить порядок без пересоздания записей.

### US-5. Поиск и навигация
Как пользователь, я хочу искать альбомы по названию/исполнителю, фильтровать по году и
исполнителю, листать результаты постранично.

### US-6. Просмотр использования песни
Как пользователь, я хочу открыть песню и увидеть список всех альбомов, в которые она входит,
с номером трека в каждом.

### US-7. Редактирование и удаление
Как пользователь, я хочу редактировать и удалять исполнителей, альбомы, песни и отдельные
треки внутри альбома.

## 4. Функциональные требования

| ID | Требование |
|---|---|
| FR-01 | Система хранит исполнителей с уникальным именем. |
| FR-02 | Система хранит альбомы: название, исполнитель (обязательная связь), год выпуска (целое число, разумный диапазон). |
| FR-03 | Система хранит песни как самостоятельные сущности с названием, не привязанные жёстко к одному альбому. |
| FR-04 | Связь альбом↔песня хранит порядковый номер трека, уникальный **в рамках альбома**. |
| FR-05 | Одна и та же песня может быть связана с несколькими альбомами одновременно, с независимыми номерами в каждом. |
| FR-06 | Внутри одного альбома одна и та же песня не может встречаться дважды. |
| FR-07 | Внутри одного альбома два трека не могут иметь одинаковый порядковый номер. |
| FR-08 | Песню, входящую хотя бы в один альбом, нельзя удалить напрямую — система сообщает, в каких альбомах она используется. |
| FR-09 | При добавлении трека в альбом можно либо выбрать существующую песню из каталога, либо создать новую тут же. |
| FR-10 | Порядок треков в альбоме можно изменить: полная замена нумерации по присланному списку ID треков. |
| FR-11 | Список альбомов поддерживает: полнотекстовый поиск (название альбома, имя исполнителя), фильтр по исполнителю, фильтр по году/диапазону лет, пагинацию. |
| FR-12 | Список песен поддерживает поиск по названию и пагинацию; карточка песни показывает все альбомы, в которые она входит, с номером трека. |
| FR-13 | Все сущности поддерживают CRUD через API и через UI. |
| FR-14 | API документирован в машиночитаемом виде (OpenAPI) и доступен для просмотра (Swagger UI). |
| FR-15 | Ошибки валидации и нарушения бизнес-правил возвращаются в едином структурированном формате с понятным сообщением. |

## 5. Критерии приёмки

- **AC-1** (US-3, ключевой сценарий): создать альбом А с песней «X» (номер 1); создать альбом Б;
  добавить в альбом Б ту же песню «X», выбрав её из каталога, с номером 5. Получить: в БД одна
  запись `Song`, две записи `AlbumTrack` с разными `position`. Удаление трека из альбома Б не
  затрагивает трек в альбоме А.
- **AC-2**: попытка добавить в альбом трек с уже занятым в этом альбоме номером — отклоняется
  с понятной ошибкой, состояние альбома не меняется.
- **AC-3**: попытка добавить в альбом одну и ту же песню повторно — отклоняется.
- **AC-4**: попытка удалить песню, используемую хотя бы в одном альбоме, — отклоняется (409),
  с указанием, в каких альбомах она используется.
- **AC-5**: reorder треков присылает список ID в новом порядке → после операции `position`
  треков равны `1..N` в этом порядке; частичный/невалидный список (не все треки альбома,
  чужой ID) — отклоняется, состояние не меняется.
- **AC-6**: список альбомов с фильтром по году и исполнителю и поиском по подстроке возвращает
  ожидаемое подмножество с корректной пагинацией (`count`, `next`, `previous`).
- **AC-7**: страница песни показывает все альбомы, в которых песня используется, с корректным
  номером трека для каждого.

## 6. Non-Goals (сознательно вне объёма)

- **Аутентификация и авторизация** — каталог открыт для чтения и записи без входа в систему.
  Причина: не входит в требования тестового задания; добавление auth увеличивает объём и риск
  без пользы для оценки основного навыка (моделирование M2M-through и работа с Vue/Django).
- Загрузка обложек альбомов и медиафайлов.
- Множественные исполнители на альбом (сплиты/сборники) — только один исполнитель на альбом.
- Мультиязычность интерфейса — только русский.
- Права доступа/роли, история изменений (audit log).
- Полнотекстовый поиск с ранжированием (используется простой `icontains`/`SearchFilter`).

## 7. Открытые вопросы

Нет открытых вопросов на момент утверждения спецификации. Диапазон допустимых лет альбома
принят как `[1860, текущий год + 1]` (1860 — ориентировочная эпоха начала звукозаписи;
запас `+1` — для анонсированных, но ещё не вышедших релизов).
